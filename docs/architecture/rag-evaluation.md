# RAG evaluation

`eval` is a uv workspace member and is not a production deployable. Compile, validate, and run the RAG harness against published modules in Postgres (`DATABASE_URL` required).

## Run batch evaluation

```bash
uv run python -m eval.rag
```

Or:

```bash
uv run rag-eval
```

Methods: `bm25` (default), `embedding`, `local_embedding`, `rag`, `local_rag`.

## Datasets

Files live under `eval/rag/golden/`.

| File | Role |
|---|---|
| `Golden_Dataset.manifest.json` | Primary modular authoring manifest. Domain shards sit under `records/`. |
| `Golden_Dataset.json` | Compiled bilingual superset. Generated by `golden-compile`. |
| `pilot_records.json` | Hand-curated Q001–Q025 pilot rows. |
| `golden_dataset.json` | Bangla-only reference rows. UUIDs may not match the current database. |

SME authoring inventories sit under `eval/rag/golden/authoring/`.

## Record shape

```json
{
  "id": "Q001",
  "question_en": "During today's visit…",
  "expected_answer_en": "Some swelling in the feet…",
  "question_bn": "…",
  "expected_answer_bn": "…",
  "source_card_id": ["1f5fb32d-13d7-4ebb-beb7-d60b6fbfab26"],
  "query_type": "Scenario-based",
  "answerable": "yes",
  "module_id": ["3f751ce8-c5fc-4a45-9bd2-6f7c4807e396"]
}
```

| Field | Required | Notes |
|---|---|---|
| `question_en`, `question_bn` | yes | Bilingual questions |
| `expected_answer_en`, `expected_answer_bn` | yes | Gold answers |
| `module_id` | yes | Published module UUIDs. Use `[]` for out-of-scope. |
| `source_card_id` | yes | `module_card.id` UUIDs. Use `[]` for Negative. |
| `query_type` | yes | See `eval/rag/golden/taxonomy.json` |
| `answerable` | yes | `yes`, `no`, or `partial` |

The loader also accepts records that store questions as locale maps instead of `question_en` / `question_bn` keys.

| `answerable` | Meaning |
|---|---|
| `yes` | In-scope. Evaluate retrieval and answer quality. |
| `no` | Out-of-scope. The model should refuse. Skipped in BM25 and embedding batch. |
| `partial` | In-scope but ambiguous. The model should clarify. |

Out-of-scope when `answerable` is `no` or `module_id` is empty.

## Authoring commands

```bash
uv run python bin/export_golden_authoring_pack.py
uv run python bin/generate_golden_expansion.py
uv run python bin/generate_golden_expansion.py --template-fallback
uv run python bin/generate_golden_expansion.py --domain anc
uv run python bin/generate_golden_expansion.py --export-prompts
uv run python bin/generate_golden_expansion.py --from-response
uv run python -m eval.rag golden-compile --manifest eval/rag/golden/Golden_Dataset.manifest.json
uv run python -m eval.rag validate --dataset eval/rag/golden/Golden_Dataset.manifest.json
uv run python -m eval.rag coverage --dataset eval/rag/golden/Golden_Dataset.manifest.json \
  --output eval/rag/reports/golden-coverage.json
```

Expansion copies hand-curated rows from `pilot_records.json` into domain shards unchanged. New records are authored per domain.

Prompt export writes `eval/rag/golden/authoring/prompts/{domain}_batch{N}.prompt.json`. Save LLM output as `{domain}_batch{N}.response.json` next to each prompt file.

## Run methods

BM25:

```bash
uv run python -m eval.rag --method bm25 --dataset eval/rag/golden/Golden_Dataset.json --language bn
```

Embedding (cloud vectors on `module.embedding`):

```bash
uv run python -m eval.rag --method embedding --dataset eval/rag/golden/Golden_Dataset.json --language bn
```

Local embedding (`module.local_embedding`):

```bash
uv run python bin/backfill_module_local_embeddings.py --missing-only
uv run python -m eval.rag --method local_embedding --dataset eval/rag/golden/Golden_Dataset.json --language bn
```

RAG chatbot:

```bash
uv run python -m eval.rag --method rag --dataset eval/rag/golden/Golden_Dataset.json --language bn \
  --output eval/rag/reports/golden-rag-run.json
```

Local RAG (`POST /coaching/local-rag-query` parity):

```bash
uv run python bin/backfill_module_card_local_embeddings.py --missing-only
uv run rag-eval --method local_rag --dataset eval/rag/golden/Golden_Dataset.json --language bn \
  --output eval/rag/reports/golden-local-rag-run.json
```

Long runs checkpoint progress every 10 records by default. Resume with `--resume` and the same `--output` path.

## Coverage targets

- At least 4 answerable records per published module
- At least 80 percent of published cards referenced in `source_card_id`
- Query-type mix from `taxonomy.json`
- Out-of-scope negatives included

Reports under `eval/rag/reports/` are generated output. Do not edit them as product documentation.
